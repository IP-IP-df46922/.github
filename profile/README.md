<p>专线解决稳定，住宅解决归属，这是最简洁的分法。但真实业务往往两者都需要，于是问题变成：钱该花在哪一边。这篇用一个决策路径把选择讲清，再给出三类业务的配置组合，最后是两个常见的错误搭配。</p>
<h2>一、两种资源的核心差异</h2>
<p>专线的价值在带宽承诺与低抖动，适合传输。住宅的价值在归属自然与地区匹配，适合登录。两者的技术实现、计价方式、运维要求都不同。</p>
<p>把传输需求交给住宅线路，会遇到带宽不足与共享争抢；把登录需求交给专线，会遇到归属偏机房的问题。用错方向，钱花了问题还在。</p>

<h2>二、决策路径</h2>
<p>第一问：业务是否要求持续大流量传输？是，看专线。第二问：账号是否对登录地敏感？是，看住宅。</p>
<p>第三问：预算是否允许两者并存？允许，就分工；不允许，按业务的主要矛盾选一个，另一个用折中方案。</p>
<h3>折中方案是什么</h3>
<p>用住宅线路承载登录，重要传输错峰进行；或者用专线承载传输，登录时切换到住宅环境。折中不是最优，但在预算受限时可用。</p>
<h2>三、三类业务的组合</h2>

<h2>四、两个错误搭配</h2>
<p>错误一，用住宅地址做直播推流。家庭上行有限，晚高峰抖动明显，画面卡顿。错误二，用专线地址登录敏感账号。归属偏机房，验证频率高。</p>
<p>两个错误的共同点是把资源用在了它不擅长的方向。纠正方式不是加预算，而是换方向。</p>
<h3>怎么判断自己用错了</h3>
<p>看症状：登录验证多，是归属问题；上传慢或掉帧，是带宽问题。两类症状对应两类资源，对症换，不要一起换。</p>
<h2>五、预算受限时的分配顺序</h2>
<p>第一顺位是登录环境。账号是业务的核心，登录地不稳，其他配置再好也没用。第二顺位是基础带宽，保证日常操作不卡。</p>
<p>第三顺位才是专线。前三项都满足之后，再把预算投到专线上。反过来先买专线、登录用共享地址，是最常见的顺序错误。</p>

<p>按这个顺序投入，每一分钱都在解决当前最痛的问题。顺序颠倒时，钱花了但痛点还在，很容易让人觉得"投入没用"。</p>
<h3>一个月度的复核清单</h3>
<p>每月复盘三件事：登录验证次数、上传失败次数、线路费用占比。验证次数上升说明归属不匹配，上传失败上升说明带宽不足，费用占比过高说明资源买多了。</p>
<p>三项放在同一张表里看，能避免"换个资源试试"的盲目调整。多数时候问题只出在一个方向上，改一处就够，别把整套配置推倒重来。</p>
<h2>常见问答</h2>
<h3>只买一种行不行？</h3>
<p>答：行，但要接受折中。预算够就分工，预算紧就按主要矛盾选。</p>
<h3>住宅线路能做直播吗？</h3>
<p>答：低码率单人直播可以，高码率多机位不行。</p>
<h3>专线能登录账号吗？</h3>
<p>答：能，但验证可能更多。敏感账号建议住宅。</p>
<h3>两者可以共用一条物理线路吗？</h3>
<p>答：可以，用分流规则区分。配置复杂一些，但成本更低。</p>
